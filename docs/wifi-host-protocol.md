# 汇海体测 WiFi 主机通讯协议

**文档性质**：独立开发与联调参考

**适用通道**：采集器／上位机与汇海 WiFi 测试主机之间的 UDP 通讯

**覆盖功能**：设备发现、成绩采集、学生名单下载与清空、校时、通讯质量检测、主机参数读写、关机、退回主界面

> 阅读本文不需要查阅客户端源码。正文优先描述线上报文和交互过程；当前参考客户端的特殊行为与兼容逻辑单独标明，已知限制汇总在附录。
>
> 本文依据现有客户端的组包与解析代码整理，尚未取得厂家完整协议、固件源码或全版本真机抓包。因此，本文可作为当前实现的开发基线，但不构成对所有主机型号和固件版本的兼容性认证。标记为“待确认”的内容不得当作已证实事实。

## 1. 阅读约定

### 1.1 基本约定

- 所有偏移均从 **0** 开始，长度单位均为**字节**。
- `BE16`／`BE32` 分别表示 2／4 字节大端无符号位模式；读入有符号 32 位整数时，最高位为 1 会得到负值。
- `CRC16` 固定为 2 字节大端。
- `D` 表示命令数据区长度，`N` 表示名单人数。
- “完整帧长”包括帧头、Len、载荷和 CRC。
- 除特别说明外，`Len` 均包含 **Len 字段自身和末尾 CRC**，不包含帧头。
- 报文样例中的字节均为十六进制；字符串示例按对应字符编码转换为字节。

### 1.2 表述层级

| 表述 | 含义 |
| --- | --- |
| 线上格式 | 当前客户端实际发送或解析的报文格式 |
| 客户端行为 | 当前参考客户端的重试、状态判断或兼容策略，不必然是固件强制要求 |
| 实现要求／建议 | 为保证新实现稳健、可维护而提出的要求或建议 |
| 待确认 | 仅凭当前证据不能确定，需要厂家资料、固件证据或真机验证 |

### 1.3 开发时最重要的边界

1. UDP 数据报边界不总是协议帧边界：名单下载会把一个完整帧拆成多个 UDP 数据报。
2. `16 02 02` 同时用于成绩数据帧和名单下载应答，但两者的 Len 宽度不同，必须结合通道和上下文解析。
3. 当前没有可确认的协议版本号或版本协商命令；两种成绩格式只能按帧长识别。
4. 帧中未读取的字段不得自行命名为“保留”“版本”或固定值。
5. “收到应答”“停止重发”“设备执行成功”是不同概念，应按各命令的返回码分别判断。

## 2. 通讯模型与设备发现

### 2.1 通道概览

| 通道 | 传输 | 默认端口 | 用途 |
| --- | --- | --- | --- |
| 发现通道 | IPv4 UDP，广播或单播 | 48899 | 发现 WiFi 模块及其返回的主机信息 |
| 命令通道 | IPv4 UDP，连接到目标 IP／端口 | 10000 | 校时、关机、参数、采集／下载预处理等 |
| 成绩采集通道 | IPv4 UDP，连接到目标 IP／端口 | 10000 | 轮询头帧和成绩数据帧 |
| 名单下载通道 | IPv4 UDP，连接到目标 IP／端口 | 10000 | 下载／清空学生及接收下载应答 |

**说明**：10000 是当前客户端使用的默认目标端口，可配置；现有证据不能证明所有固件都固定监听该端口。

业务 Socket 在参考客户端中连接目标 IP／端口后收发，不显式绑定本地地址或本地端口。对端 IP 是实际通讯隔离的第一层依据，HostID 是报文内的第二层标识。

### 2.2 发现请求

向 `255.255.255.255:48899` 广播，或向指定主机 IP 的 48899 端口单播：

```text
www.usr.cn
```

- 编码：ASCII。
- 不附加 NUL、换行或其他尾部字节。
- 参考客户端对广播应答的默认收集时间为每个本地 IPv4 地址 5000 ms；单播默认最多等待约 5000 ms。

### 2.3 发现应答

参考客户端按 ASCII 解码，并接受以下结构：

```text
IP,未使用字段,主机信息,未使用字段
```

要求：

- 逗号分隔后恰好 4 段。
- 第 1 段作为 IP。
- 第 3 段按下划线拆分，至少 3 段。
- 第 3 段第 1 部分提取数字，作为 `HostID`。
- 第 3 段第 2 部分提取数字，作为 `PhysicalID`。
- 第 3 段最后一部分作为 `SerialNumber`。

示例：

```text
192.168.1.50,field2,H1_P6_SN123,field4
```

可解析为：

| 字段 | 值 |
| --- | --- |
| IP | `192.168.1.50` |
| HostID | 1 |
| PhysicalID | 6 |
| SerialNumber | `SN123` |

参考客户端按 `SerialNumber` 对广播结果去重。HostID／PhysicalID 按单字节解析，失败时为 0；IP 和序列号不做进一步格式校验。

**待确认**：上述格式是当前发现解析器接受的格式，不代表所有 USR 模块或所有固件都使用相同文本。`PhysicalID` 只能确认为“发现信息中的物理编号”，不能据此认定为主机型号、硬件版本或协议版本。

## 3. 通用编码、CRC 与接收组帧

### 3.1 多字节整数与字符编码

| 内容 | 编码／字节序 |
| --- | --- |
| Len、SerNo、序号、参数中的多字节整数 | 大端 |
| 二进制成绩中的 Int32 | 大端有符号 Int32，二进制补码 |
| 名单学号、卡号 | ASCII，右侧补 `00` |
| 名单姓名、班级 | GB2312，右侧补 `00` |
| 成绩姓名 | GB2312 |
| 成绩学号 | 从 ASCII 字母数字区域提取，详见 §6.5 |
| 学号范围命令 | 当前客户端使用系统默认编码，右侧补空格 `20` |
| 时间范围命令、文本成绩 | 当前客户端使用系统默认编码及当前区域文化 |
| 旧格式项目代码、记录时间 | BCD 转换规则见 §6.5 |

独立实现若需跨平台一致行为，建议将学号范围限定为 ASCII 数字文本，将文本成绩和时间范围限定为 ASCII，并使用固定区域文化；这是否被全部固件接受仍需联调确认。

### 3.2 CRC16-CCITT

| 参数 | 值 |
| --- | --- |
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| 输入／输出反射 | 无 |
| 异或输出 | 无 |
| 线上 CRC 字节序 | 大端 |

校验向量：ASCII `123456789` 的 CRC 为 `0x29B1`。

所有业务帧的 CRC 均从 **Len 字段首字节**开始，计算到 **CRC 前一个字节**：

```text
帧头 | Len | 其余载荷 | CRC16
       ^---- CRC 计算范围 ----^
```

- 4 字节帧头的请求：CRC 从帧偏移 4 开始。
- 3 字节帧头的应答：CRC 从帧偏移 3 开始。
- CRC 不覆盖帧头，也不覆盖 CRC 自身。

### 3.3 接收缓冲区与组帧

实现者应把同一对端的接收数据视为需要重新组帧的字节序列，至少支持：

1. 扫描已知帧头，不假定帧一定从缓冲区偏移 0 开始。
2. 根据帧头及当前通道确定 Len 是 1 字节还是 2 字节。
3. 在数据不足时保留缓冲区，等待后续数据报。
4. 完整帧长度为 `3 + Len`（3 字节帧头）或 `4 + Len`（4 字节帧头）。
5. 取帧后先检查最小长度，再读取字段并验证 CRC。
6. 对未知帧头、非法长度、CRC 错误和超时采取可恢复的丢弃／重同步策略，不能在同一个坏包上无限循环。

参考客户端每次 Socket 接收缓冲为 1024 字节；超过该大小的 UDP 数据报不会由该封装自动还原成完整报文。名单下载发送端则明确把大帧按 1024 字节拆成多个数据报，因此接收端必须支持跨数据报重组。

## 4. 帧类型与通用命令

### 4.1 帧类型总表

| 帧头 | 方向 | 用途 | Len |
| --- | --- | --- | --- |
| `16 16 01 01` | PC → 主机 | 通用命令 | 2 字节大端 |
| `16 01 01` | 主机 → PC | 通用命令应答 | 2 字节大端 |
| `16 0A 0A` | 主机 → PC | 读参数应答 | 2 字节大端 |
| `16 16 02 02` | PC → 主机 | 成绩数据请求 | 1 字节 |
| `16 03 03` | 主机 → PC | 成绩数据头帧 | 1 字节 |
| `16 02 02` | 主机 → PC | 成绩数据帧 | 1 字节 |
| `16 16 0A 0A` | PC → 主机 | 学生下载／清空命令 | 2 字节大端 |
| `16 02 02` | 主机 → PC | 学生下载应答 | 2 字节大端 |

### 4.2 通用命令请求

```text
16 16 01 01 | Len(2,BE) | SerNo(2,BE) | HostID | Cmd | Sub1 | Sub2 | Data... | CRC16(2,BE)
```

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | 帧头 `16 16 01 01` |
| 4 | 2 | Len = `10 + D` |
| 6 | 2 | SerNo，命令流水号 |
| 8 | 1 | HostID |
| 9 | 1 | Cmd |
| 10 | 1 | Sub1 |
| 11 | 1 | Sub2 |
| 12 | D | Data，可为空 |
| 末尾 | 2 | CRC16 |

完整帧长为 `14 + D`。

SerNo 用于关联同一命令的重发。参考客户端对普通命令使用进程内静态 16 位流水号，首次为 0，递增并在 65535 后回绕；重发复用原流水号。并行实例之间不保证唯一，因此新实现不应把 SerNo 当作全局事务 ID。

### 4.3 通用命令应答

```text
16 01 01 | Len(2,BE) | SerNo(2,BE) | HostID | Cmd | 未确认(2) | CMDState | 可选数据... | CRC16(2,BE)
```

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 3 | 帧头 `16 01 01` |
| 3 | 2 | Len |
| 5 | 2 | SerNo |
| 7 | 1 | HostID |
| 8 | 1 | Cmd，回显命令字 |
| 9 | 2 | 当前客户端未读取，语义待确认 |
| 11 | 1 | CMDState |
| 12 | 可变 | 可选返回数据；读取主机号时使用偏移 12 |
| 末尾 | 2 | CRC16 |

字段互不重叠时，无附加数据的布局至少为 14 字节；包含偏移 12 的一字节返回值时至少为 15 字节。参考解析器没有完整执行这些最小长度检查，新实现应执行。

已知 CMDState：

| 值 | 当前客户端解释 |
| --- | --- |
| `B3` | 命令执行成功／数据就绪 |
| `E0` | 终止等待的状态之一，具体固件含义待确认 |
| `E1` | 终止等待的状态之一，具体固件含义待确认 |
| `E2` | 终止等待的状态之一，具体固件含义待确认 |

新实现建议同时匹配帧类型、SerNo、HostID、Cmd，并验证 CRC 后再采用 CMDState。若目标部署允许广播或共享监听端口，应特别避免把其他主机的应答误认为当前命令应答。

### 4.4 命令一览

| Cmd | 功能 | Sub1 | 数据区 | 成功依据 |
| --- | --- | --- | --- | --- |
| `0A` | 读取主机参数 | `00` | 无 | 收到 CRC 合法的参数应答 |
| `0A` | 写入主机参数 | `00` | TLV 参数块 | `CMDState=B3` |
| `0B` | 读取主机号 | `00` | 无 | 返回值位于应答偏移 12 |
| `A1` | 主机关机 | `00` | 无 | `CMDState=B3` |
| `A3` | 采集预处理 | 见 §6.1 | 依 Sub1 | `CMDState=B3` |
| `A4` | 下载学生预处理 | `00` | 无 | `CMDState=B3` |
| `A5` | 校时 | `00` | 7 字节 | `CMDState=B3` |
| `A6` | Echo 通讯检测 | `00` | 200 字节 | 参考客户端只看 `CMDState=B3` |
| `AF` | 退回主界面 | `00` | 无 | 参考客户端的返回判断不可靠，见 §5.4 |

除采集预处理外，当前公开命令的 Sub1／Sub2 均为 0；采集预处理的 Sub2 也为 0。

## 5. 基本控制命令

### 5.1 读取主机号（Cmd `0B`）

无数据区。参考客户端从通用命令应答的偏移 12 读取 1 字节主机号。

**实现注意**：参考客户端只检查应答总长度至少 13 后读取该偏移，未可靠验证 CRC、帧类型、Cmd 和 CMDState；长度 13 时偏移 12 实际已落入末尾 CRC。新实现不应复制该判断，应至少确认应答包含独立的返回值字节且不与 CRC 重叠。

### 5.2 校时（Cmd `A5`）

数据区固定 7 字节，**纯二进制，不是 BCD**：

| 数据偏移 | 内容 |
| --- | --- |
| 0 | 年 − 2000 |
| 1 | 月 |
| 2 | 日 |
| 3 | 星期：0=周日，其余与常见 `DayOfWeek` 数值一致 |
| 4 | 时 |
| 5 | 分 |
| 6 | 秒 |

报文不携带时区。固件支持的年份范围待确认；发送端应自行限制 `年−2000` 可由 1 字节表达。

### 5.3 Echo 通讯质量检测（Cmd `A6`）

发送 200 字节递增数据：

```text
00 01 02 ... C7
```

参考客户端只发送一次并等待 1000 ms，仅以 CRC 合法且 Cmd 匹配的 `CMDState=B3` 记为成功，**不逐字节比较回显载荷，也不核对 SerNo／HostID**。

因此，参考客户端统计的是“命令成功应答率”，不是严格的数据无差错率。若新实现需要检测载荷完整性，应另外比较返回数据；返回数据在应答中的完整布局仍需真机确认。

### 5.4 关机与退回主界面

- 关机：Cmd `A1`，无数据区，以 `CMDState=B3` 为成功。
- 退回主界面：Cmd `AF`，无数据区。

参考客户端对 `AF` 仅在最后状态为 `E0～E2` 时返回失败；完全未收到应答时状态保持 0，也会返回成功。因此该布尔结果不能作为设备已退回主界面的证据。

## 6. 成绩采集协议

成绩采集分两种客户端模式：

| 模式 | Flag | 预处理 | 完成条件 |
| --- | --- | --- | --- |
| 事后采集 | `11` | 先发送 Cmd `A3` | 收到 `DataBytes=0` 的有效头帧 |
| 实时采集 | `00` | 不发送 Cmd `A3` | 不按 `DataBytes=0` 自动结束 |

### 6.1 采集预处理（Cmd `A3`，仅事后采集）

| Sub1 | 范围 | 数据区 |
| --- | --- | --- |
| `51` | 当前客户端称为“新记录” | 无 |
| `52` | 全部记录 | 无 |
| `53` | 学号范围 | 40 字节：起始学号 20＋结束学号 20 |
| `54` | 时间范围 | 通常为 20 字节：起始时间文本 10＋结束时间文本 10 |
| `55` | 记录序号范围 | 4 字节：起始 SN(BE16)＋结束 SN(BE16) |

学号范围：

- 每个字段固定 20 字节。
- 当前客户端使用系统默认编码，右侧补空格 `20`。
- 新实现应限制编码后不超过 20 字节，避免跨字段覆盖。

时间范围：

```text
yyMMddHHmmyyMMddHHmm
```

前 10 字节为起始时间，后 10 字节为结束时间。当前客户端按当前区域文化格式化并使用系统默认编码；跨平台实现建议明确采用 ASCII 数字和固定的两位年、月、日、时、分。

序号范围请求只携带 16 位序号。范围是否包含端点、空边界的含义、“新记录”的判定及已采集标记更新时机均待固件确认。

### 6.2 成绩数据请求

```text
16 16 02 02 | Len(1)=0E | HostID | Flag | 00 | 00 00 | 00 00 | LastSN(2,BE) | 00 00 | CRC16(2,BE)
```

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | 帧头 `16 16 02 02` |
| 4 | 1 | Len，固定 `0E` |
| 5 | 1 | HostID |
| 6 | 1 | Flag：事后 `11`，实时 `00` |
| 7 | 1 | 固定发送 `00`，语义待确认 |
| 8 | 2 | 固定发送 `00 00`，语义待确认 |
| 10 | 2 | 固定发送 `00 00`，语义待确认 |
| 12 | 2 | LastSN，本机已接受的最后记录序号 |
| 14 | 2 | 固定发送 `00 00`，语义待确认 |
| 16 | 2 | CRC16 |

完整帧长固定 18 字节。

LastSN 初始为 0。参考客户端在每收到一条通过 CRC、HostID 和适用连续性检查的记录后更新它，即使成绩内容无效也会更新。

**兼容限制**：即使接收到 4 字节序号，后续请求仍只发送 LastSN 的低 16 位。超过 65535 后续传行为待真机确认，不能宣称已完整支持 32 位序号续传。

### 6.3 成绩头帧

#### 18 字节布局

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 3 | 帧头 `16 03 03` |
| 3 | 1 | Len = `0F` |
| 4 | 1 | HostID |
| 5 | 4 | DataBytes，BE32，本次数据总字节数 |
| 9 | 2 | MaxSN，BE16，当前客户端用于进度 |
| 11 | 2 | 未读取，语义待确认 |
| 13 | 2 | LastSN，本批最后一条记录序号 |
| 15 | 1 | EOF：值为 `07` 时客户端解析为 true |
| 16 | 2 | CRC16 |

#### 24 字节布局

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 3 | 帧头 `16 03 03` |
| 3 | 1 | Len = `15` |
| 4 | 1 | HostID |
| 5 | 4 | DataBytes，BE32 |
| 9 | 4 | MaxSN，BE32 |
| 13 | 4 | 未读取，语义待确认 |
| 17 | 4 | LastSN，BE32 |
| 21 | 1 | EOF：值为 `07` 时客户端解析为 true |
| 22 | 2 | CRC16 |

解析注意：

- 参考客户端以“总长度是否等于 18”选择布局；**一切非 18 长度都会进入 24 字节布局分支**，没有严格检查长度必须等于 24。
- DataBytes、MaxSN、LastSN 被读入有符号 Int32；4 字节字段最高位为 1 时会成为负数。
- DataBytes 除零值完成判断外，当前客户端未用于核对累计数据长度。
- EOF 会被解析，但当前采集流程不使用 EOF 判定完成。
- 事后采集以 `DataBytes=0` 为整个采集完成条件；`SN==头帧.LastSN` 只表示本批结束，之后仍继续轮询。

### 6.4 成绩数据帧

| 相对偏移 | 62 字节格式 | 64 字节格式 |
| --- | --- | --- |
| 0 | 帧头 `16 02 02`，3 字节 | 同左 |
| 3 | Len = `3B` | Len = `3D` |
| 4 | HostID | HostID |
| 5 | 未读取，语义待确认 | 同左 |
| 6 | SN，BE16，2 字节 | SN，BE32，4 字节 |
| 8／10 | 52 字节成绩记录体，从偏移 8 开始 | 52 字节成绩记录体，从偏移 10 开始 |
| 末尾 | CRC16，偏移 60～61 | CRC16，偏移 62～63 |

参考客户端的序号连续性规则：

```text
若 LastSN != 0 且未启用“允许不连续”：
    要求 当前SN == LastSN + 1
否则：
    接受当前SN
```

- 首条记录不要求 SN 为 1。
- 不连续时结束当前批次并继续后续轮询。
- 学号范围采集在参考 UI 中允许不连续；其他模式默认要求连续。
- 对未知帧长，参考客户端不会复制有效记录体，但 SN 属性会把一切非 62 字节帧都按 4 字节序号读取。新实现应显式拒绝未知长度，而不是沿用这一回退行为。

### 6.5 52 字节成绩记录体

| 记录体偏移 | 长度 | 字段 | 编码 |
| --- | --- | --- | --- |
| 0 | 20 | 学号 | ASCII 字符区域，特殊还原见下文 |
| 20 | 1 | 测试项目代码 | 62 字节帧按 BCD；64 字节帧为原始字节 |
| 21 | 5 | 成绩 | 二进制、特殊值或文本 |
| 26 | 5 | 记录时间 | BCD：yy MM dd HH mm |
| 31 | 1 | 性别＋学号来源 | 见下文 |
| 32 | 20 | 姓名 | GB2312 |

#### 学号提取与还原

参考客户端从 20 字节字段的尾部向前扫描：

- 保留 `0-9`、`A-Z`、`a-z`。
- 跳过空格。
- 已收集字符后遇到其他非空格字节则停止。
- 转为大写。

若结果为 8 位、包含 A～F 且每两位均可解析为十六进制字节，则将 4 字节按**小端无符号整数**还原为十进制字符串：

```text
ABCD1234 → 字节 AB CD 12 34 → 小端整数 873647531
```

这只是客户端对特定学号编码的兼容算法，不等同于把字符串当作大端十六进制数解析，也不应无条件应用到其他长度。

#### 成绩字段

| 首字节 | 后 4 字节及换算 |
| --- | --- |
| `E0` | BE32 有符号整数；项目 6、81 ÷10；项目 15、16、100 ÷1000；其他原值 |
| `E1` | BE32 有符号整数，统一 ÷1000，不再应用 `E0` 的项目换算 |
| `A0` | 犯规 Foul |
| `A1` | 弃权 Abandoned |
| `A2` | 未完成 Incomplete |
| 其他 | 全部 5 字节按系统默认编码解码为文本并解析十进制；项目 6 且结果 `<10` 时 ×100 |

特殊成绩忽略后 4 字节，数值 Result 保持默认 0；该 0 不是有效数值成绩。数值解析失败应标记记录无效，而不是当作 0 分。

文本成绩使用当前区域文化解析，未固定小数点。项目 6 的 `<10` 判断没有非负下限，独立实现如需修改该行为，应先确认与既有数据的兼容性。

#### 记录时间

5 字节依次为：

```text
yy MM dd HH mm
```

每字节按以下方式转换：

```text
值 = (高4位 × 10) + 低4位
```

年份为 `2000 + yy`，秒固定为 0。转换算法本身不验证半字节是否小于等于 9；之后通过日期构造检查范围。日期无效时参考客户端回退为 `2000-01-01 00:00`，且不会仅因此把成绩标记为无效。

合法单字节 BCD 只能表达 0～99；不能据此认定 62 字节格式能按标准 BCD 表示所有大于 99 的项目代码。

#### 性别与学号来源

若字节为 ASCII：

| 值 | 性别 | 学号来源 |
| --- | --- | --- |
| `30`（字符 0） | 女 | Unknown |
| `31`（字符 1） | 男 | Unknown |

否则：

- 低 4 位：0=女，1=男，其他=“无”。
- 高 4 位按 `byte & F0` 取学号来源，不右移。

| 掩码后的值 | 来源 |
| --- | --- |
| `00` | Unknown |
| `40` | 按键输入 |
| `50` | IC 卡物理卡号 |
| `60` | IC 卡学号 |
| `80` | 扫描枪 |
| `90` | 身份证 |

客户端枚举另有 `HostStoredData=10`（十进制），但 `byte & F0` 不可能得到 10，因此当前 WiFi 解析不会产生该来源。

#### 姓名

20 字节按 GB2312 解码后执行普通首尾空白裁剪。NUL（`00`）不属于普通空白，可能保留在字符串中；接收方如需以 C 字符串处理，应明确处理 NUL 填充。

### 6.6 推荐采集状态机

```text
事后采集：发送 A3 预处理
实时采集：直接进入轮询

轮询：
  发送成绩数据请求（携带本机 LastSN）
  等待有效头帧
  若事后模式且 DataBytes=0：完成
  否则按头帧接收数据帧：
      校验帧长、HostID、CRC、序号连续性
      解析并保存记录
      更新本机 LastSN
      若 SN=头帧.LastSN：本批结束，继续轮询
  超时、坏包或断线：按实现策略重试，不得把本批结束当作全部完成
```

参考客户端每轮先等待 1000 ms 再发送；收到头帧后，事后模式的数据结束等待上限为 600 秒，实时模式为 5 秒。它还在事后 15 秒、实时 60 秒无任何接收活动时判定掉线。以上属于客户端策略，不是线上格式要求。

## 7. 学生名单下载与清空

### 7.1 交互顺序

推荐按当前客户端流程：

```text
PC → 主机：Cmd A4，下载学生预处理
PC → 主机：一个或多个名单分组命令
PC → 主机：下载结束命令 Cmd 11
```

清空流程：

```text
PC → 主机：Cmd A4，下载学生预处理
PC → 主机：清空学生命令 Cmd EE
PC → 主机：参考客户端仍会发送下载结束命令 Cmd 11
```

`A4` 成功后是否必须等待特定设备状态、遗漏 `11` 是否影响名单固化，以及 `EE` 后是否必须发送 `11`，均待固件或真机确认。

### 7.2 下载命令帧

```text
16 16 0A 0A | Len(2,BE) | SerNo(2,BE) | HostID | Cmd | Sub | Data... | CRC16(2,BE)
```

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | 帧头 `16 16 0A 0A` |
| 4 | 2 | Len |
| 6 | 2 | SerNo |
| 8 | 1 | HostID |
| 9 | 1 | Cmd |
| 10 | 1 | Sub，当前固定 0 |
| 11 | 可变 | Data |
| 末尾 | 2 | CRC16 |

| Cmd | 功能 | Len | 完整帧长 |
| --- | --- | --- | --- |
| `00` | 下载正式学生名单 | `13 + 72×N` | `17 + 72×N` |
| `80` | 下载测试学生名单 | `13 + 72×N` | `17 + 72×N` |
| `11` | 下载结束 | 9 | 13 |
| `EE` | 清空主机内全部学生 | 9 | 13 |

SerNo 在参考客户端中为实例级 16 位递增流水号，重发保持不变。

### 7.3 名单数据区

```text
学生数(1) | 记录长(1)=48 | 01 | 00 | 学生记录 × N
```

其中记录长 `48` 是十六进制，即 72 字节。两个固定字节 `01 00` 的固件语义待确认，**不得解释为协议版本号**。

完整帧中的位置：

| 相对偏移 | 字段 |
| --- | --- |
| 11 | 学生数 N |
| 12 | 记录长 `48` |
| 13 | 固定 `01` |
| 14 | 固定 `00` |
| 15 | 第一条学生记录 |

### 7.4 单条学生记录（72 字节）

| 记录偏移 | 长度 | 字段 | 编码／值 |
| --- | --- | --- | --- |
| 0 | 20 | StudentID | ASCII，右侧补 `00` |
| 20 | 20 | Name | GB2312，右侧补 `00` |
| 40 | 1 | Sex | `31`=男，`30`=女 |
| 41 | 1 | Grade | 当前固定 `00` |
| 42 | 20 | ClassName | GB2312，右侧补 `00` |
| 62 | 10 | CardID | ASCII，右侧补 `00` |

实现注意：

- 字符串按编码后的字节数截断到字段宽度；直接截断可能破坏 GB2312 双字节字符。新实现宜在字符边界截断，但须先与固件验证兼容性。
- 参考客户端仅当 Sex 为“男”或字符串“1”时发送 `31`，其他值均发送 `30`。
- 公共模型中的 Grade 属性不参与编码，当前线上值固定为 0。
- N 线上只有 1 字节，应保证 `1≤N≤255`。N=256 会绕回 0，却仍附带 256 条记录，必须拒绝。
- `null` 或空数组不是合法的“零人名单”命令；需要清空时应使用 Cmd `EE`。

### 7.5 下载应答

虽然与成绩数据帧共用 `16 02 02` 帧头，但此处的 Len 是 **2 字节大端**：

```text
16 02 02 | Len(2,BE) | SerNo(2,BE) | HostID | Command | Sub | CommandRet | CRC16(2,BE)
```

| 相对偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 3 | 帧头 `16 02 02` |
| 3 | 2 | Len |
| 5 | 2 | SerNo |
| 7 | 1 | HostID |
| 8 | 1 | Command |
| 9 | 1 | Sub |
| 10 | 1 | CommandRet |
| 11 | 2 | CRC16 |

已知 CommandRet：

| 值 | 含义 |
| --- | --- |
| `00` | 接收成功 ReceiveSucceeded |
| `11` | 接收失败 ReceiveFailed |
| `22` | 存储成功 StorageSucceeded |
| `33` | 存储失败 StorageFailed |
| `44` | 存储器已满 StorageFull |
| `55` | 清除成功 ClearSucceeded |
| `66` | 清除失败 ClearFailed |

参考客户端在 CRC 合法、SerNo／Sub 一致且 CommandRet 不为 `11` 时停止重发；它不匹配 HostID／Command。停止重发不等于业务成功，调用方仍须检查 CommandRet。

新实现建议匹配 SerNo、HostID、Command、Sub，并分别处理“收到但失败”“存储失败”“存储已满”和无应答超时。

### 7.6 UDP 分包

单个名单协议帧超过 1024 字节时，参考客户端拆成多个 UDP 数据报：

- 每个数据报最多 1024 字节。
- 数据报之间发送休眠 20 ms。
- 分包只是同一协议帧的连续片段，**不分别添加帧头和 CRC**。

例如 100 人名单：

```text
完整帧长 = 17 + 72×100 = 7217
分包长度 = 1024×7 + 49
```

## 8. 主机参数读写（Cmd `0A`）

### 8.1 读参数

发送无数据区的 Cmd `0A`。主机返回：

```text
16 0A 0A | Len(2,BE) | 未确认(7) | TLV... | CRC16(2,BE)
```

| 相对偏移 | 字段 |
| --- | --- |
| 0～2 | 帧头 |
| 3～4 | Len |
| 5～11 | 当前参数解析器未读取，语义待确认 |
| 12 至 CRC 前 | TLV 参数区 |
| 末 2 字节 | CRC16 |

虽然该区域可能与其他应答共享布局，但当前参数解析代码没有读取其中的 SerNo、HostID 或 Cmd，独立实现不得仅凭位置相似就把这些字段语义视为已确认。

### 8.2 TLV 结构

```text
块长(1) | 参数ID(1) | 数据(块长−2)
```

块长包含块长字节自身。读取 ID=1 时兼容块长 4，缺少的“人工确认”字段补 0。

| 参数 ID | 写入块长 | 数据字段顺序，未注明长度均为 1 字节 |
| --- | --- | --- |
| 1 | 5 | 按键学号：最大长度、递增间隔、人工确认 |
| 2 | 4 | 输入设备：扫描枪／身份证、IC 卡物理号 |
| 3 | 5 | 测试结果：确认方式、写入 IC 卡、LED 屏显示 |
| 4 | 4 | 辅助设备：无线音箱、红外防抢跑器 |
| 5 | 6 | 测试限制：测试次数、总时间(BE16)、进行方式 |
| `81` | 3 | 引体向上：难度系数 |
| `82` | 9 | 地毯式中长跑：跑道长度(BE16)、男生距离(BE16)、女生距离(BE16)、测试模式 |
| `83` | 4 | 标签式中长跑：圈数、测试模式 |
| `84` | 3 | 仰卧起坐：躺平模式 |
| `85` | 3 | 短跑系列：项目选择 |

开关和模式字段保留原始字节值，各取值含义待设备协议确认。

### 8.3 写参数

发送 Cmd `0A`，Data 为 TLV 参数块。参考客户端固定按上表顺序发送全部 10 块：

```text
5 + 4 + 5 + 4 + 6 + 3 + 9 + 4 + 3 + 3 = 46 字节
```

- Len = `10 + 46 = 56`，即 `00 38`。
- 完整命令帧长 = `14 + 46 = 60` 字节。
- 未赋值属性也按 0 写入，不存在“只写已赋值属性”的逻辑。
- 读取时未知 ID 被跳过，重复 ID 由后出现的块覆盖；未知块不会在再次写入时自动保留。
- 两字节字段在线上只有 16 位，发送端应限制在 `0～65535`。

实现者应验证块长至少为 2、块长不超过剩余缓冲区、已知参数的数据长度足够，再读取字段。CRC 合法不代表 TLV 结构合法。

## 9. 主机身份、流水号与协议版本

### 9.1 标识的区别

| 标识 | 长度／形式 | 用途 | 是否进入业务报文 |
| --- | --- | --- | --- |
| IP＋端口 | 网络地址 | 确定 UDP 对端 | 不作为帧字段 |
| HostID | 1 字节 | 主机号；采集时筛选头帧／数据帧 | 是 |
| PhysicalID | 发现文本中的数字 | 物理编号 | 否 |
| SerialNumber／HostSN | 字符串 | 发现去重、界面及成绩来源信息 | 否 |
| SerNo | BE16 | 命令及重发关联 | 是，但不是设备序列号 |
| 记录 SN | BE16／BE32 | 成绩记录顺序及续传位置 | 是，但不是设备序列号 |

因此：

- `SerialNumber` 是发现信息中的设备序列号；`SerNo` 是命令流水号，两者不能混用。
- `HostSN` 在当前采集器中被保存并用于成绩来源信息，但不参与 WiFi 请求组包或响应解析。
- 当前实现不能仅凭协议字段可靠识别主机型号。

### 9.2 主机号校验范围

| 通道 | 当前客户端校验 |
| --- | --- |
| 成绩头帧／数据帧 | 匹配 HostID |
| 普通命令 | 匹配 CRC、Cmd 和状态；不匹配 HostID／SerNo |
| 名单下载 | 匹配 CRC、SerNo、Sub；不匹配 HostID／Command |

因此当前实现的主机隔离首先依赖 UDP 对端 IP。HostID 并非所有通道都强制校验的统一身份认证机制，也不提供防伪造能力。

### 9.3 版本结论

当前协议实现中**没有发现**：

- 协议版本号、固件版本号或主机型号字段；
- 查询版本／型号的命令；
- 连接后的版本协商；
- 按版本号选择解析器的逻辑；
- 能力位或功能协商。

当前只有以下**按格式兼容**的行为：

1. 头帧总长 18 走 2 字节序号布局；其他长度走 4 字节序号布局。
2. 成绩帧 62／64 字节分别对应 2／4 字节序号和不同记录体偏移。
3. 参数 ID 1 兼容块长 4 和 5。

这些是报文格式分支，不是已确认的版本号或版本协商。

以下内容不得擅自解释为版本：

- 帧头中的 `01 01`、`02 02`、`0A 0A`；
- 名单数据区固定的 `01 00`；
- 命令应答、头帧、成绩帧中的未读取区域；
- 客户端程序集版本 `1.0.0.0`。

若未来需要支持多种主机或固件，建议通过真机抓包建立“主机型号／固件版本／帧格式／能力”矩阵；在未取得版本查询手段前，只能按帧长和能力实测做兼容，不应虚构版本映射。

## 10. 独立实现要求与联调验收

### 10.1 接收解析

- [ ] 按通道区分 `16 02 02` 的 1 字节／2 字节 Len。
- [ ] 支持跨 UDP 数据报重组名单命令。
- [ ] 校验帧最小长度、Len 与完整帧长、字段边界和 CRC。
- [ ] 未知帧长、未知命令和畸形 TLV 不导致越界或死循环。
- [ ] 坏包后能够丢弃、重同步并继续接收后续帧。
- [ ] 不将未读取字段默认解释为 0、保留位或版本号。

### 10.2 命令与状态

- [ ] 重发复用同一 SerNo，并为命令设置总超时和最大重试次数。
- [ ] 区分无应答、CRC 错误、应答不匹配、设备返回失败和业务成功。
- [ ] 下载检查 CommandRet，不把停止重发当作存储成功。
- [ ] 事后采集只有收到 `DataBytes=0` 的有效头帧才判定全部完成。
- [ ] 不把单批 `LastSN` 到达或 EOF 单独当作全部采集完成。

### 10.3 数据安全

- [ ] 名单人数限制为 1～255，并限制字符串编码后的字段宽度。
- [ ] 空名单不通过下载命令表达；清空使用独立命令并进行操作确认。
- [ ] 特殊成绩不与数值 0 混淆，文本成绩解析失败应标记无效。
- [ ] 记录序号超过 65535 时，不假定现有 16 位 LastSN 请求可以正确续传。
- [ ] 校时、参数写入、关机和清空命令具有明确日志及错误处理。

### 10.4 最小联调用例

1. CRC 向量 `123456789 → 29B1`。
2. 发现广播和指定 IP 单播，核对 HostID、PhysicalID、SerialNumber。
3. 校时后读取设备时间，确认年、星期和秒。
4. Echo 检查成功应答；若需数据完整性，另验回显内容。
5. 读取全部参数，修改后回读，确认未知参数处理策略。
6. 分别采集 62 和 64 字节成绩帧，覆盖二进制、文本、特殊成绩、非法日期和中文字符。
7. 验证空批次、多批次、序号不连续、丢包、重复包和超时恢复。
8. 下载 1 人、100 人和多组名单，验证跨 UDP 数据报重组及 CommandRet。
9. 验证存储失败、存储已满、清除失败和无应答，不只测试成功路径。
10. 若设备记录序号可超过 65535，单独验证续传，不以离线解析结果替代真机结论。

## 附录 B：报文样例

以下样例均按本文算法离线构造并校验 CRC，不是现场抓包。HostID 均为 1。

### B.1 下载学生预处理

SerNo=0，Cmd=`A4`，无数据区：

```text
16 16 01 01 00 0A 00 00 01 A4 00 00 D5 98
```

- Len=`00 0A`，即 10。
- 完整帧长 14。
- CRC 范围：`00 0A 00 00 01 A4 00 00`。

### B.2 事后采集首次轮询

Flag=`11`，LastSN=0：

```text
16 16 02 02 0E 01 11 00 00 00 00 00 00 00 00 00 B7 F5
```

- Len=`0E`，即 14。
- 完整帧长 18。
- CRC 范围：`0E 01 11 00 00 00 00 00 00 00 00 00`。

### B.3 清空学生与下载结束

以下两帧由当前名单组包器离线生成，SerNo 依次为 0、1：

```text
清空学生：
16 16 0A 0A 00 09 00 00 01 EE 00 BD A1

下载结束：
16 16 0A 0A 00 09 00 01 01 11 00 C8 EA
```

两帧均为 Len=9、完整帧长 13，CRC 从偏移 4 的 Len 开始计算。

## 附录 C：当前参考客户端行为与限制

这些内容用于理解现有采集器，不应直接当作协议规范复制到新实现。

1. **普通命令重试**：默认最多尝试 `int.MaxValue` 次，每次等待应答 1000 ms，随后再等待结束信号 1000 ms；没有短时的整条命令总超时。
2. **提前停止重发**：收到命令或参数包后先通知发送线程，再完成 CRC／Cmd 等检查；可能因不匹配包提前停止重发。
3. **坏命令应答风险**：命令应答 CRC 不合法或 Cmd 不匹配时，当前接收循环可能不推进包指针并持锁空转。
4. **短头帧门槛**：采集接收缓冲累计不足 62 字节时不扫描头帧，因此单独到达的 18／24 字节头帧不会立即解析；下一轮请求还会清空缓冲。
5. **非严格新格式判断**：头帧一切非 18 长度走 4 字节序号分支；成绩 SN 一切非 62 长度走 4 字节分支。
6. **32 位续传不完整**：可接收 4 字节 SN，但请求 LastSN 仍为 2 字节。
7. **下载空响应异常**：`null／空数组` 不生成有效命令数据；工作状态下发送可能空引用。持续重发后仍无有效应答时，下载公开方法直接读取空响应的 CommandRet，也可能空引用。
8. **下载结束调用**：下载和清空流程的 `Close()` 都发送 Cmd `11`，不检查其是否成功；排队实例尚未进入工作状态时可能只等待而未实际发出。
9. **并发限制**：事后采集和学生下载各有独立的 4 台工作队列；实时采集不受该队列限制。这是客户端资源管理，不是协议限制。
10. **源码来源**：当前协议代码从原 `Device.dll` 反编译恢复；离线一致测试不能替代真机联调。

## 附录 D：证据边界与待确认事项

以下内容不能仅靠当前客户端源码确定：

- 不同主机型号、硬件版本、固件版本与报文格式的对应关系。
- 帧中未读取区域和固定字节的真实语义。
- `E0／E1／E2` 三种命令状态的分别含义。
- “新记录”的判定及已采集标记何时更新。
- 各范围采集是否包含端点、空边界的含义。
- 下载结束命令与名单固化之间的准确关系。
- Echo 返回载荷的完整布局。
- 参数开关、模式字段的全部取值含义。
- 大于 65535 的记录序号续传行为。
- 大于 99 的项目代码在 62 字节格式中的实际编码方式。

开发过程中如取得厂家协议或真机抓包，应优先用新证据更新本文，并明确记录适用的主机型号和固件版本。
